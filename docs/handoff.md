```

git config --global user.name  "Himanshu Sengar"

```

**Clone** (use `git clone`, not "Download ZIP" — a ZIP has no history and can't push):
```bash
cd ~/Desktop
git clone https://github.com/himansh308/DevTinder.git

```

**Backend:**
```bash
cd ~/Desktop/DevTinder
npm install                    # repo's .npmrc forces the public npm registry
cp .env.example .env           # then fill in .env (table below)
npm run seed -- --fake 200     # local MongoDB: test accounts + 200 generated developers
npm run dev                    # http://localhost:7777
```
The default seed command wipes users and connection requests, and is restricted to a local MongoDB.
For a development Atlas database, `MONGO_URI` can point to Atlas and this opt-in preserves existing
records, adding only missing sample accounts and connections:
```bash
npm run seed -- --atlas --fake 200
```
Existing user profiles, passwords, and connection-request statuses are not overwritten. Only newly
created sample accounts use the shared test password below. If `you@test.com` already exists, its
password is preserved, so the sample password is guaranteed only when the seed creates that account.
Do not use sample data in a production database.

### Backend `.env`
| Variable | Value | Notes |
|---|---|---|
| `JWT_SECRET` | `openssl rand -hex 32` | New random value; changing it just logs everyone out |
| `OTP_SECRET` | `openssl rand -hex 32` | Required — forgot password fails with "OTP_SECRET is not set" without it |
| `MONGO_URI` | `mongodb://127.0.0.1:27017/devtinder` | Local default. For development Atlas, use its URI and the explicit `--atlas` seed option; never seed production or put a real password in `.env.example`. |
| `NOMINATIM_CONTACT_EMAIL` | `himanshu.thakur2812@gmail.com` | Identifies the app to Nominatim; not per-user |

The frontend has no `.env` yet (API URL is hardcoded — see "next").
Its API calls use `http://localhost:7777`; the backend currently allows the frontend origin
`http://localhost:5173` with credentialed requests. Run both dev servers on those origins for the
current cookie-based login flow.

### Frontend routes and backend API
The frontend route `/feed/preferences` is the preferences screen; it saves settings through
`PATCH /profile/preferences` (not an API route named `/feed/preferences`). Other frontend API paths
match the backend routes:
- Auth: `POST /signup`, `/login`, `/logout`, `/forgotPassword`, `/resetPassword`
- Profile: `POST /profile/view`, `PATCH /profile/edit`, `PATCH /profile/preferences`, `DELETE /delete`
- Feed and requests: `GET /feed`, `POST /request/send/:status/:toUserId`,
  `POST /request/review/:status/:requestId`
- Connections: `GET /user/connections`, `/user/requests/received`,
  `/user/mutual-connections/:candidateId`
- Location: `PATCH /user/location`, `GET /location/search`, `/location/reverse`

## 2. Tests

Backend running + seeded data required.
```bash
npm run test:routes    # 67 checks: every route with valid + invalid input
npm run test:otp       # OTP hardening: hash storage, 5-guess lockout, 50-parallel race, expiry, reuse
```
Before/after pattern for any refactor: `npm run test:routes > before.txt`, change code, run again into
`after.txt`, compare. Answers can depend on data state (e.g. an expired OTP left on an account gives
"Time Limit exceeded" instead of "OTP is Incorrect").

## 3. What's done

**Course (S2 Ep 1–19)** — auth (signup/login/logout, JWT cookie), profile edit, connection requests
(send/review), connections, requests received, feed with pagination, the whole React UI.

**Custom features**
- Feed preferences (gender, age range, max distance) — frontend page `/feed/preferences`, backend API `PATCH /profile/preferences`
- Location: auto GPS on visit, manual Nominatim search, reverse geocoding, sticky manual override
  (`locationAutoSync`) — see frontend `notes/location-feature-end-to-end.md`
- Mutual-connection badges + detail page (batched counts, no N+1)
- Account deletion (type-DELETE modal), forgot/reset password (OTP), about-me bio
- Seed script with faker

**Security / quality**
- Old `GET /user` (account takeover) and unauthenticated `GET /feed` deleted
- NoSQL injection closed; **zod validation on every route** (`src/validation/schemas.js`, `src/middlewares/validate.js`)
- OTP: `crypto.randomInt`, HMAC storage, `timingSafeEqual`, 5-guess cap with atomic `$inc`
- Password hashes and OTP fields stripped from every response (`toJSON`)
- Frontend: every protected page guarded on every navigation; autofill fixed with `autoComplete`
- Public npm registry pinned via `.npmrc` in both repos

## 4. What's next (priority order)

1. **Feed stops after 10 people** — `Feed.jsx` loads `/feed` once (backend default limit 10); load the next page when cards run low.
2. **No indexes on `connectionrequests`** (only `_id`) — every feed/connections/requests query scans the whole collection. Add indexes on `fromUserId`/`toUserId`.
3. **Probable duplicate-request race** in `/request/send` (`findOne` then `save`, no unique index) — prove with a parallel test, fix with a unique index on the user pair.
4. **Finish the security audit** (`notes/security-audit-2026-10-07.md`): rate limiting on `/login` + `/forgotPassword` (closes the "new OTP after every lockout" loop), cookie flags (`httpOnly`, `sameSite`), one generic login error message, sessions surviving logout/reset, delete-account leaving requests behind, `helmet`.
5. **Silent failures on 9 frontend pages** — catch blocks only `console.log`; show an error or toast.
6. **Config into `.env` before deploying** — backend: CORS origin `localhost:5173`, port `7777`; frontend: 20 hardcoded `localhost:7777` → one axios instance with `VITE_API_URL`.
7. **Season 3: deploy** (AWS EC2 + nginx + domain).
8. **Features:** block / unmatch / remove connection (designed — separate `Block` collection; removed connections keep a `removed` status so they don't reappear), Nodemailer (OTP by email, then signup verification + MX check + disposable-email block), photo upload (multer, drag-and-drop), instant match, real-time chat.

Smaller: empty lists returned as 400 errors (`/user/connections`, `/user/requests/received` should return `[]`), schema's default `photoUrl` is a Google search page not an image, pre-filled test credentials in `Login.jsx`, `/mututalConnections` typo, stale `// TODO` in `ForgotPassword.jsx`, debug `console.log`s in `Connection.jsx`/`Request.jsx`, existing lint warnings (setState in effects, effect deps), location note still lists two fixed bugs as open, delete merged remote branches, roadmap tracker out of date.

Longer-term plans: `docs/roadmap.md` (phases 0–6, resume bullets) and `docs/infrastructure-plan.md`
(Docker → Redis → Prometheus/Grafana → Elasticsearch → Kafka → Kubernetes).

## 5. How work has been done (keep doing this)

- **One branch per change** (`fix/...`, `feature/...`), push the branch, test in the browser, then merge to `main`.
- **Before/after evidence** for refactors — record route behaviour first, compare after.
- **Test global switches against real queries** — e.g. Mongoose `sanitizeFilter` blocks the attack but also broke the feed's own `$in`/`$nin`/`$near`; rejected for that reason (`notes/nosql-injection.md`).
- **Notes for anything confusing** — backend `notes/` (topics + `notes/walkthroughs/` for line-by-line traces), frontend `notes/`. Explanations work best as literal value traces through frontend *and* backend.
- **Personal project: public tools only** — npm from `registry.npmjs.org` (the `.npmrc`), no company accounts, services or data.
